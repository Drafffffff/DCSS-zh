# Item tutorial hints producer review

This batch covers `native/crawl-ref/source/hints.cc`: `_hints_target_mode()`, `_hints_abilities()`, `_hints_throw_stuff()`, and all visible text branches in `hints_describe_item()`. The stable IDs live in `localization/migration/luna-item-hints-messages.json`. It deliberately models producer branches and structural arguments; it does not attempt to reverse-match the final concatenated paragraph.

## Source-to-ID coverage

- `_hints_target_mode(false/true)`: `item.hints.target_mode.fire` and `.spell`. The fixed `<w>+</w>`, `<w>-</w>`, `<w>f</w>`, `<w>Enter</w>`, and `<w>.</w>` tokens remain literal. The repeat command generated from `%f`/`%ap` is the sole `key_markup` argument.
- `_hints_abilities()`: three un-equipped prerequisites (`.weapon`, `.armour`, `.jewellery`), `.equipped`, and `.bug` for the defensive impossible-base-type branch. Command-key arguments are `key_markup`. The `%i` item-slot shortcut is represented as the full chord `<w>=i</w>` after `insert_commands`, not as the raw `%i` source token. This helper's tail has been included in each full sentence so the caller can retain the original `To do this, …` phrasing.
- `_hints_throw_stuff()`: four complete variants distinguish inventory slot present/absent and singular/plural quantity. `item_slot` is a raw `key` wrapped by the template in `<w>…</w>`; the fire command is `key_markup`; `item_name` is the singular item base name and the source's plural branch adds literal `s`. `target_suffix` is the complete target-mode helper output. The localized templates avoid an English plural suffix.
- Weapons: identified artefact with ability; identified artefact with resistance (with optional tile mouse clause); unequipped weapon command help; skill-training gap warning; wielded ranged (keyboard and Tiles click+keyboard variants); wielded melee. The skill warning only applies when current skill + 2 is below the resolved best weapon skill. The source wraps both `skill_name()` results in `<w>…</w>`; the templates preserve those wrappers around `name` args and reuse existing reviewed atoms (`Long Blades` → 长刃, `Axes` → 斧术, etc.). The screen command is `key_markup`.
- Missiles: throwable branch has full item name and delegates to throw helper. Non-throwable missiles produce no visible paragraph.
- Armour: horns/hard helmet prohibition; barding restriction; ordinary wear/remove help; the three independent character-specific warnings (Magic Character/body armour, Magic Character/shield, Ranger/offhand); unidentified unusual-description warning; and independent wearable resistance and ability paragraphs. Conditions and command args are documented per ID. Resistance/ability text can both occur after the base armour text.
- Wands: common evoke instruction plus separate Tiles variants for Web, fullscreen/non-local, and windowed local UNIX builds. The target-yourself and click-on-wand alternatives are retained. The corresponding `USE_TILE` branch is absent in non-Tiles builds.
- Scrolls, jewellery, potions, books/manuals, corpses, staves, and miscellany: IDs cover every visible branch, including ring vs amulet resistance wording, optional Tiles click wording, Trog staff branch, and manual vs spellbook.

Every visible message ID and added fixed atom has one concrete oracle case with dynamic names, command keys, and optional clauses resolved into canonical and localized output. Command key inputs use the same rendered value for canonical and localized forms (for example, `<w>%</w>` for `CMD_RESISTS_SCREEN`, `<w>m</w>` for `CMD_DISPLAY_SKILLS`, `<w>A</w>` for `CMD_DISPLAY_MUTATIONS`, `<w>W</w>`/`<w>T</w>` for armour wear/remove, and `<w>P</w>`/`<w>R</w>` for jewellery wear/remove), based on `cmd-keys.h`/`insert_commands`; user remappings are runtime arguments, never translated; each key/key-markup fixture asserts canonical equals localized. The apostrophe swap key and full `<w>=i</w>` item-slot adjustment chord are also preserved. The cases exercise all helper and visible item branches, including each Tiles wand variant and character-specific warning. Empty returns are control-flow outcomes and intentionally have no display message ID. No visible string should be emitted for non-throwable missiles or the identified artefact weapon branch with neither ability nor resistance.

## Argument and markup policy

`key_markup` arguments represent the exact `<w>…</w>` sequence produced by `insert_commands`; the producer must keep the original command choice (`CMD_*`) and supply its generated key at the matching placeholder. Optional Tiles clauses are whole `text` arguments and may contain source markup such as `<w>right mouse button</w>`; keep the localized clause and tags together. Stable fixed IDs now cover the reusable avatar-right-click, armour click, jewellery inventory click, scroll click, and potion click clauses. Ring/amulet type words also have dedicated IDs (`item.hints.jewellery.type.ring` / `.amulet`) and are supplied as `name` atoms, rather than being hardcoded by the caller. Item/god/skill display names use `name`; composed helper outputs such as the full ability prerequisite and target-mode tail use `text`. The outer tutorial color wrapper is controlled by `MSGCH_TUTORIAL` and remains outside these message templates. The code's `<r>` diagnostic style in the impossible ability branch is preserved.

The source concatenates scroll/potion literals without a separating space before the Tiles alternative (`"this scroll" "or simply click…"`, likewise potion). The catalog templates provide natural localized spacing, while canonical English must be kept faithful to the exact current generated string if used for Lua/control output; this source seam should be corrected or handled as an explicit canonical override during integration. Do not add whitespace through a translation of the assembled output.

## Limits

The tutorial prose often combines multiple independent paragraphs in one returned string. The IDs in this batch are typed, complete branch fragments for source-level assembly; do not flatten them into a single generic `{description}` message. Preserve source condition order, blank lines, and the final tutorial color boundary in the producer. Where optional state cannot be represented safely (for example, missing dynamic item name or command key), use whole-branch English fallback. Do not silently keep an English name inside an otherwise localized sentence.
