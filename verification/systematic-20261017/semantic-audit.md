# Systematic semantic audit: level terms and composed messages

## Catalog scan

Scanned `native/crawl-ref/source/zh-catalog.inc` for every entry whose English key contains `level` or `levels` and whose Chinese value contains `层`. This yielded **141 matching rows, 109 distinct source keys**. The repeated rows are duplicate/generated catalog entries. Reviewed all distinct keys against the C++ source and their displayed use.

Of those keys, floor/place/depth meanings are appropriate for 107 distinct keys. The outliers are:

- `Fixed Level` (catalog rows 6479 and 42555) is currently translated as “固定层数”. In `item-name.cc:1160`, it names `BOOK_RANDART_LEVEL`; `makeitem.cc:1536` selects the spell difficulty and `randbook.cc` builds a book from spells constrained to that spell level. It means a spell-level book, never a dungeon floor. Added “固定等级法术书”.
- `Fixed Levels` (catalog row 41802) has the same wrong Chinese value, but no current C++ source string was found for that English key. It appears to be a stale/orphan catalog entry, so it was not added as a source-backed translation.

All remaining distinct matches refer to a dungeon floor, branch depth, a count of floors, or travel/map terminology: examples include “this level”, “level %d of the Abyss”, “levels deep”, “on level %d of”, “interlevel travel”, “levels seen”, stair hints, floor annotations, portals, and item origin text. These translations use “层/楼层/本层” appropriately. The bare key `levels` means a count of floors in its catalog use; no matching C++ display literal was found outside the catalog, so it remains a low-context entry rather than evidence of a rank mistranslation.

## Rank and progression review

- **Character XP level:** `main.cc:1754-1787`, `ouch.cc:461`, `player.cc:3011-3030`, and `ability.cc:2169-2170`. Catalog translations generally use 等级/级 appropriately. The Coglin ability requirement counts experience levels, not floors. Luna entries cover the level progress, cap, extra-life XP estimates, and ability message.
- **Skill rank:** `skills.cc:335-343`, `describe.cc:1587,2171`, and `notes.cc:295-302`. Existing gain messages and attack-delay descriptions use rank wording. The note fragment `Reduced skill … to level …` was mistranslated as “至等级”; added the complete assembled milestone. The source’s `NOTE_GAIN_SKILL` counterpart already describes reaching a skill rank.
- **Spell difficulty vs. memorization capacity:** `spl-book.cc:1052-1054` compares available `player_spell_levels()` with a spell’s required slots. The catalog’s “等级的法术” wording is unclear, so an explicit spell-slot message was added. Spell-difficulty labels such as “You cannot cast spells above level 4” correctly mean level/rank and use 级.
- **Spell-learning milestone:** `notes.cc:242-245` assembles `Learned a level ` + spell difficulty + ` spell: ` + title. The existing fragment “学会了等级” is malformed in this construction; added the complete runtime form “学会了%d级法术：%s”.
- **Mutation rank:** `describe.cc:4864-4868` appends ` (level %d/%d)` for a mutation with multiple ranks. The catalog already uses 等级 here; Luna’s separate title suffix uses the compact rank form.
- **God/ability rank:** `mutation.cc`’s demonspawn schedule says a mutation is gained at character level `%d`; its catalog uses 等级 correctly. The Coglin ability’s XP-level message is covered above. No wrong floor translation was found in these reviewed rank-bearing entries.

## Dynamic templates and plural expansion

The C++ builds some player-facing strings from a format plus English suffix arguments. Translating only the format can leave the suffix in English. The new entries use the actual expanded singular/plural forms where source code chooses a conditional `"s"`:

- `spl-book.cc:879`: “%d spell level left” / “%d spell levels left”. Both use the same single integer placeholder. The source condition also supplies “ left ” or “s left”; the full runtime templates avoid exposing that English suffix.
- `spl-book.cc:1104`: “Memorise … spell level …” / “… spell levels …”. After expanding the conditional plural suffix, the five remaining placeholders are title, cost, remaining capacity, optional separating space, and optional warning. Their order and types are unchanged.
- `spl-selfench.cc:148`: “Forget … spell level …” / “… spell levels …”. After expanding its suffix, the four remaining placeholders are title, cost, resulting capacity, and optional warning.

The earlier draft used `%.0s` to hide the suffix parameter. That was removed: the source format’s printf tokens must remain unchanged, and the final entries describe completed runtime variants instead. Existing monster-examine entries already pair singular and plural forms for notice chance and hit chance. `describe.cc:6749` composes Foxfire’s damage dice with `fire damage`; the added complete sentence retains the dynamic dice value and clearly distinguishes the element from the `Fire` ranged-action label in `quiver.cc`.

## Repair priority

1. **P1, meaning changes gameplay comprehension:** correct “Fixed Level” and spell-level capacity phrasing; keep dungeon floors (“层”) distinct from XP, skill, mutation, and spell ranks (“级”).
2. **P1, dynamic text can leak English:** use complete singular/plural outputs for the three conditional-suffix formats, complete assembled level-up/skill notes, and complete monster damage sentences.
3. **P2, contextual fragments:** inspect other multi-part item, spell, god, and overview strings as they are encountered; a standalone `level` glossary entry cannot establish whether the runtime meaning is floor, rank, depth, or capacity.
4. **P3, low-context or debug text:** keep isolated generic labels and non-player diagnostics out of bulk replacement unless a real display context is identified.

## Scope and limits

This pass reviewed all 141 catalog rows matching the requested `level` + “层” scan and examined key C++ contexts for character XP, spell memorization, skill rank, mutation rank, and god/ability progression. It also searched all C++ source `level` occurrences and focused on display strings; most matches were identifiers, comments, or diagnostics. The pass does not execute every menu, note, item, or monster combination and does not establish that every game string is correct. The new JSON’s actual printf formats preserve their tokens and argument order; entries representing stream-assembled runtime sentences document their conceptual substitutions and are not claimed to be printf source literals.

## Additional runtime-composition review: encounter, danger, combat, terrain, travel

Reviewed the screenshot-triggered dynamic message families against `player-notices.cc`, `nearby-danger.cc`, `melee-attack.cc`, `mon-util.cc`, `directn.cc`, `travel.cc`, `feature-data.h`, and `player.cc`. The Luna review JSON now contains complete templates rather than isolated English fragments for these user-facing paths.

- `player-notices.cc:398-443`: encounter lines stream-compose `You encounter ` + `_describe_monsters_from_species()` + `.`; this description can itself contain articles, count phrases, and plural species. Orb pursuit uses a separate plural-agreement branch (`appears` for one, `appear` for more than one) and appends a trailing separator for follow-up notices. Both full forms are recorded.
- `nearby-danger.cc:145-167,239+`: the stop/unsafe warning for a single visible monster is dynamically `%s is nearby!`; groups use `There are monsters nearby!`; sensed unseen threats use `There is a strange disturbance nearby!`. The latter warnings are also the source of the stop-autoexplore behavior. `travel.cc:761-816` has distinct normal completion/partial exploration feedback; this pass did not add every run-state message (e.g. key interrupt or travel-excluded position), which should be checked in a broader travel UI pass.
- `melee-attack.cc:3528-3631` selects fixed action verbs, then emits attacker, optional stealth modifier, verb, defender, and optional charge/damage/weapon/punctuation suffixes. `mon-util.cc:2074-2115` supplies the normal attack-type verbs; `melee-attack.cc:3528-3600` adds killer-klown and haunted-armour random verbs plus shadow-stab/tentacle special cases. The JSON records singular/plural completed forms for those source-backed choices, their action translations, and completed `does no damage` patterns. Captures are retained in source order. The optional charge/effect and weapon/afar values are themselves composed strings, so the fixed-verb rows do not establish every nested suffix as translated.
- `directn.cc:2966-2987` emits `There is ` + either the fixed shop entrance prefix or `feature_description_at()` + ` here.`. A feature description can include article, door state, covering modifiers such as “spattered with blood”, and marker-provided details. The atomic `%s` feature template prevents these English internal components from appearing in the wrong Chinese order. The source path uses singular `There is`; no `There are` variant is emitted here.
- `player.cc:220-229` builds the unsafe-trap prompt with a movement verb, `onto` for pressure plates/alarm traps or `into` for other traps, and a basename description. `player.cc:205-211` has the distinct Zot-trap prompt. Both complete paths are included.
- `travel.cc:5106-5177` constructs discovery reports from counted/stated findings. If there are duplicate feature names or the list is too wide, it prints `Found %s %s.` with number words and category. Otherwise it prints `Found ` + a comma-separated assembled list + `.`; each singleton gets an article and each repeated feature gets a count and `pluralise()` that explicitly protects feature qualifiers such as `leading`, `back to`, `to`, `of`, `in`, `out of`, `from`, and `back into`. This explains why the screenshot’s “Found three staircases leading out of the Dungeon” is a single full discovery sentence and why quantity cannot be translated as a floor count. Stair destinations and orientations come from feature names in `feature-data.h` and `directn.cc`, including “staircase leading out of the dungeon”, “staircase to …”, and branch returns “staircase back to …”; these should be translated as destination/travel descriptions, not depth terminology.

### Validation and remaining limits

The JSON parses successfully and a token scan confirms each entry retains the same printf-style placeholder sequence in English and Chinese. Expanded encounter/terrain/discovery stream templates are documented as faithful runtime forms with their capture semantics. The attack inventory is source-backed, but this review is not an exhaustive audit of nested combat effect strings, all ranged attacks, every marker-supplied feature name, every travel-stop reason, or every UI output in the game. In particular, the generated plural verb form follows Crawl’s source `conjugate_verb` behavior (which conjugates only the first word of multiword verbs), including forms that may sound unusual in English; they document reachable source outputs rather than editorial rewrites.

## Final dynamic-phrase refinement: encounter count and door modifiers

The general encounter template remains `You encounter %s.` → `你遭遇%s。`. `player-notices.cc:443` appends the complete `_describe_monsters_from_species()` phrase; that capture carries the species/count/article semantics. The Chinese template does not add “one rat” or hardcode any species. Oracle wording for a source capture rendered as `老鼠` therefore follows this same reviewed general phrase.

For floor features, `directn.cc:2966-2987` assembles `There is ` + `feature_description_at(..., DESC_A)` + ` here.`. The feature routine appends cover descriptions after the noun: `, spattered with blood`, `, covered with ice`, or `, temporary`; it also selects door state and marker-defined description pieces. Added natural complete forms for blood-spattered open/closed/runed doors, a generic blood/ice/temporary modifier pattern, and the common `There is an open door here.` sentence. The Chinese uses “一扇敞开的门” and places “溅满鲜血” after the noun; the catalog fragment “open door” remains useful elsewhere and is not the preferred wording for the complete sentence.

Accessory equipment continuation/completion variants now use “佩戴” while capturing the item name after “your”, so an amulet name such as “amulet of faith” becomes “你继续佩戴信仰护符” without an English possessive fragment. Other gear continues to use the general wear/wield forms appropriate to its category.
